# Generator and maker

tenet reads entities with reflection; generated code makes that faster and
gives queries typed field names. The maker writes entities, migrations and
fixtures for you through the project console.

## Setting up a project

```bash
go run github.com/smatify/tenet/gen/cmd/tenet init --dialect postgres
```

writes `cmd/console` (the project console), the entity package
(`--entities`, default `internal/entity`) and the migrations package
(`--migrations`, default `migrations`; `--format go|sql`). The console reads
the database address from `TENET_DATABASE_URL`; `go run ./cmd/console list`
shows every command.

## make:* commands

| Command | Writes |
|---|---|
| `make:entity [Name]` | a new entity or more fields of an existing one, asked for one by one: type, length, nullable, unique, relations (the inverse side is added to the other entity), and its repository |
| `make:embeddable [Name]`, `make:trait [Name]` | a reusable struct of mapped fields |
| `make:migration` | a migration from the differences between the entities and the database ([migrations](migrations.md)) |
| `make:fixtures [Name]` | a fixture for `fixtures:load` |
| `make:generate` | the generated code of the entities, anew |

`make:entity --style go` writes exported fields instead of the default
Doctrine style (unexported fields with getters and setters that call
`tenet.Touch` for lazy loading); `--uuid` gives new entities a UUIDv7
identifier, `--timestamps` `created_at` and `updated_at`. `-n` asks nothing
and takes the defaults.

## Generated code

Each entity package gets an `entities_tenet.go` (`// Code generated by
tenet. DO NOT EDIT.`) with

- accessors for every mapped field, so loading and writing entities needs no
  reflection, and
- field references (`entity.PostFields.Title`) for queries: a renamed field
  breaks the build instead of a query at run time.

The maker regenerates it after each change. After editing entities by
hand, run `make:generate` or

```bash
go run github.com/smatify/tenet/gen/cmd/tenet generate [--accessors [--entity A,B]] [dir...]
```

`--accessors` also writes the missing getters and setters of fields added
by hand to Doctrine style entities. An entity without generated code still
works, through reflection.

## Checking code

```bash
go run github.com/smatify/tenet/gen/cmd/vet ./...
```

reports string field names in queries the entity does not have and field
accesses of Doctrine style entities without `tenet.Touch` (which would
skip lazy loading).
